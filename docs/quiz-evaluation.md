# リアルタイム出題のモデル比較

管理者でログインし、画面右下の「出題比較」を開きます。

1. Difyの出題ワークフローのモデルを変更して公開します。最初は問題生成・正答・誤答・整形を同じモデルに揃え、プロンプト・検索設定は固定します。
2. 「出題比較」で試行名、実際のモデル構成、設定メモ（公開版・temperature・推論設定・教材・ケース番号など）を記入し、「設定を保存して計測を開始」を押します。これは記録用ラベルであり、Difyの設定を変更する機能ではありません。
3. **同じタブ**でチャットへ戻り、普段の「問題生成」を押します。「問題を出して」など、リアルタイム出題に振り分けられた入力も対象です。普通の会話・解説・問題プールの取得は計測しません。
4. 比較ページに戻り「記録を更新」「CSVをダウンロード」を使います。問題文の下に保存済みの選択肢を表示します。CSVでは「選択肢A〜D」の各列で確認でき、全選択肢を収めた「選択肢JSON」も残ります。過去の記録も保存済みの選択肢を表示・出力します。自分の管理者アカウントの記録だけ取得できます。CSVは全件（最大1万件）、画面は最新100件です。試行名の完全一致で絞れます。
5. 比較が終わったら「計測を停止」。タブを閉じる／ログアウトでも計測設定は解除されます。記録はDBに残ります。

## 比較条件

まず10種類の会話状況を各モデル3回ずつ試すなど、同じ開始条件を繰り返してください。会話・直前の問題と回答・Difyの会話履歴や会話変数・検索資料を揃えます。モデルを切り替えながら同じ会話を継ぎ足す比較では、履歴の差が混ざります。アプリのチャット履歴とDify会話IDの両方を新しい状態にし、同じ会話を再現してください。

入力条件と依頼文はCSVに保存されますが、Dify内部の全履歴、プロンプト、検索結果、モデル設定を完全に復元するものではありません。対応するDify公開版や教材を保存し、設定メモに残してください。

## 計測の意味

- `表示までms`：出題ボタン（またはチャット送信処理の開始）から、チャットメッセージがReactで描画された後の2回目のanimation frameまで。ブラウザーによる描画タイミングの概算です。読み上げ完了や選択肢の操作可能時刻は含みません。
- `API応答までms`：ブラウザーのAPI送信からJSON受信まで。エラー応答も対象。
- `サーバー処理ms`：アプリサーバー内のDify連携・形式検証・問題保存まで。計測記録自体の保存時間は除外（画面待ち時間には含まれます）。
- `Dify通信ms`：出題APIへの送信と受信に要した時間。会話変数取得は含めません。
- `Dify送信回数`：接続先候補への試行回数。2回以上の記録は再試行の影響があるため分けて比較してください。
- トークン・費用・通貨・Dify報告latencyは `metadata.usage` の報告値のみを記録します。欠損はnull（CSVは空欄）で、0とは区別します。**全ノード合計・再試行合計を保証しません**。料金表からの推定、為替換算、Difyクレジット換算はしません。
- `使用量の範囲=dify_response_unverified` は集計範囲未確認を意味します。メッセージIDや実行IDがあればDifyログとの照合に利用できます。
- `success` は形式を満たす問題を発行できたことです。内容の正確性を保証しません。CSV末尾の正確さ・関連・難易度・解説（各1〜5）、採用可否、評価メモを人が記入してください。正解の誤り・複数正解は不採用にします。

生成に失敗しても、サーバーが応答を処理できたものは保存します。サーバーに届かない通信エラーやサーバー停止は記録できません。表示通知が届かない、背景タブ、チャット欄が非表示、履歴の復元などでは表示時間を捏造せず空欄にします。DB保存に失敗した場合は出題を妨げず、ブラウザーに計測保存失敗を通知します。

既存の `DATABASE_URL` を使用し、`quiz_evaluations` テーブルは既存のスキーマ初期化で自動作成します。追加の環境変数やAPIキーは不要です。生成原文と正解・解説は管理者用記録にのみ保存し、通常の出題レスポンスには追加しません。CSVはUTF-8 BOM付きで、日本語・改行・引用符・式として解釈される文字列を処理します。
