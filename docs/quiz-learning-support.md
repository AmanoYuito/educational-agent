# 教材の根拠と追加解説

問題カードと採点結果に「教材の根拠を見る」を表示します。出題時に保存した教材本文を読み込みます。本文はモデルに引用を創作させず、通常出題ではDify応答の `metadata.retriever_resources` から保存します。Difyで引用・出典情報が返されない場合や、以前の問題に本文の記録がない場合は、記録がない旨を表示します。別の教材を検索して代用しません。表示は出題に参照された範囲であり、正答を支える箇所の自動検証を意味しません。

問題プールの新規生成では、ナレッジAPIから取得してDifyへ渡した本文を `sourceContext` として生成結果に含めます。問題保存APIの既存 `source_context` 欄に保存すると、プールから出題する際にも問題ごとの教材を保持します。既存のプールに本文が保存されている場合も利用します。

不正解の新しい採点結果では、選んだ選択肢と正答の違いを追加解説します。「なぜBは違う？」「もっと簡単に」「具体例で教えて」でも解説を切り替えられます。正解時は後者2つを利用できます。資料の記録がない場合は、保存済みの問題・解説を参照した説明と明示します。

## 接続・保存

- `GET /api/quiz-learning/?quizId=...`: ログイン本人に発行された問題の教材本文のみを取得します。
- `POST /api/quiz-learning/`: 問題IDと `mistake` / `simple` / `example` を受け取り、DBの問題・正答・採点済み回答・教材から追加解説を生成します。未回答の問題には使えません。
- 会話用の既存 `DIFY_KEY` / `DIFY_API_KEY` と `DIFY_URL` を利用します。問題プール用キーは使いません。既存の `explain_quiz` モードと、問題内容を含む質問文を送ります。別問題の会話履歴が混ざらないよう、新規会話として実行します。
- 解説は `issued_quizzes.quiz.learningSupport` に種類別に保存します。同じ種類の成功済み解説は再生成しません。DBテーブルの追加・移行は不要です。
- 追加解説は別のLLM呼び出しです。問題生成の比較記録にある時間・トークン・費用には含めません。不正解時の初回自動解説と、未取得の種類を選んだ際に追加の利用が発生します。
- APIキー、正答、教材はブラウザーから指定させません。問題表示用の公開データには正答や解説を追加せず、教材は明示的に開いたときに取得します。

## 確認

採点・出題・追加解説の自動テスト、型検査、本番ビルド、およびAPIをモックした実画面でのPC/スマートフォン操作確認を実施します。実際のDify公開フローでの生成は別途確認が必要です。
