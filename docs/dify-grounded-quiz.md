# 教材に基づくリアルタイム出題フロー

修正版: `AITuberKit-2-grounded.yml`。提供された `AITuberKit-2.yml` を基に作成しています。問題プール用ではありません。

## 取り込み

1. Difyのスタジオで「DSLファイルをインポート」から修正版を読み込みます。アプリ名は「AITuberKit 教材根拠付き」です。元のアプリは比較・切り戻し用に残してください。
2. 「知識検索」で接続先のナレッジが選択されているか確認してください。元のナレッジ参照を引き継いでいますが、インポート環境によって再選択が必要な場合があります。
3. ナレッジ内の対象ドキュメント名が `johokiso3-1-2.html` であることを確認してください。教材範囲チェックはこの名前を使用します。登録名が異なる場合は「教材範囲を確認」の `ALLOWED_DOCUMENTS` を実際の対象教材名に変更してください。別教材まで許可しないでください。
4. プレビューで `mode=generate_question`、質問「問題を1問生成してください。」を入力します。実行履歴で、検索結果・根拠引用・問題と選択肢を確認します。
5. 正常な出題と根拠不足時の停止を確認してから公開してください。新しいアプリとして公開した場合、AITuberKit側のDify接続設定をそのアプリのAPIキーに切り替える必要があります。APIキーはチャットに貼り付けず、従来の設定場所へ入力してください。

この作業ではDSLファイルの作成とローカル検証まで実施しました。Difyへのインポート、ナレッジ検索の実行、実際のLLM生成、公開、接続設定の切り替えは未実施です。

## 変更内容

出題経路:

テーマ選択 → 知識検索 → 教材範囲を確認 → 問題生成 → 正答生成 → 誤答生成 → 整形・教材照合 → 根拠と出題形式を検証 → 回答

- 知識検索の入力を、存在しない `ユーザー入力.sys.query` 参照から、実際に選ばれたテーマへ変更しました。
- 検索結果のうち、対象教材名と一致するチャンクだけを残し、4つのLLMすべてのコンテキストとプロンプトに渡します。空の場合はLLM実行前に停止します。
- 4つのLLMに、教材だけで正誤を判断できる問題・選択肢・解説を作るよう指定しました。Few-shotに含まれていた教材外の用語を削除しました。
- 問題と正答には引用元IDと原文引用を要求し、整形ノードで全選択肢の正誤も教材に照らして確認します。
- 最後のコードノードで、引用の実在、正解の語句が引用に含まれること、4択・正解番号・重複・対応関係などを確認します。教材抜粋にない英字用語（DNS、MX、CNAMEなど）も拒否します。
- 失敗時はDifyの実行をエラーで停止し、問題を返しません。現在のAITuberKitでは出題失敗として扱われます。詳細はDifyの実行履歴で確認できます。
- 成功時は既存の `type/public.question/public.choices/answerIndex/answer/explanation` 形式を返します。引用・判定内容は中間ノードの実行履歴に残ります。

出題用4モデルの `gpt-5.6`、会話用の `gpt-5.4-mini`、依存プラグインのバージョン、通常会話経路は維持しています。追加のLLMノードはありません。ただし教材と根拠をプロンプトに含めるため、以前のフローよりトークン数や時間が増える可能性があります。モデル比較では新しい試行名を使い、変更前と区別してください。

## 検証と限界

ローカルで10件のテストを実施しました。正常な教材内の出題、空・別教材・混在した検索結果、MX問題、架空の引用、未知の用語、根拠不足、正解番号の不整合などを確認しています。YAMLの読み込み、ノード接続、参照先、検証を迂回しない回答経路、埋め込んだコードとテスト対象の一致も確認しました。

引用が本当に問題や選択肢の意味を裏付けるかは整形LLMの判定を含みます。コードが保証するのは引用の実在などの構造・文字列条件であり、教材との意味的な一致を完全に保証するものではありません。実際の教材検索とLLM出力による確認は必要です。

正解を教材の語句から直接抜き出す制約と、英字用語のチェックは保守的です。妥当な言い換えも停止する場合があります。停止が多い場合は、チェックを外す前に実行履歴で教材の登録名・取得チャンク・引用・生成文を確認してください。画像・リンク先の内容は、ナレッジがテキストとして取得していない限り根拠に使いません。
