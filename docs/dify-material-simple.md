# 教材参照・シンプル版

取り込み用ファイル: [AITuberKit-2-material-simple.yml](../AITuberKit-2-material-simple.yml)

元の `AITuberKit-2.yml` を基準に、問題生成 → 正答生成 → 誤答生成 → 整形の4つのLLMとモデル設定を維持しています。通常会話の処理も維持しています。

## 変更点

- 「ナレッジ入力」のランダム選択コードを削除し、「教材の検索文」テンプレートに置き換えました。会話テーマがあれば利用し、なければ教材内の電子メール関連のテーマで検索します。テンプレートは文字列を組み立てるだけで、LLMを呼びません。
- ナレッジ検索の対象を、文書名が `johokiso3-1-2.html` と一致する資料に限定しました。
- 4つの出題用LLMのコンテキストを検索結果に接続しました。問題・正答・誤答・解説は資料の記載だけを使い、一般知識で補わないよう指示しています。
- 前の教材根拠付き版に追加したPython検証ノード、根拠引用の生成、原文との文字列一致検査はありません。資料不足の場合は `insufficient_material` を返します。
- 既存アプリが読む問題JSONの形式は維持しています。

## プロンプトの構成

出題用4つのLLMに、Role（担当役割）、CoT（出力しない短い判断手順）、Few-shot（成功例と資料不足例を各1件）を追加しました。[各プロンプトの全文](dify-material-prompts.md)で確認・コピーできます。通常会話のLLMは今回の出題用プロンプト修正の対象外です。

例の知識が出題に混ざらないよう、例には架空の装置を用い、今回の教材とは区別しています。根拠が足りない場合は例や一般知識から補わないよう明記しました。思考過程の出力は要求せず、既存のJSONと短い解説だけを返します。

例と手順を追加したため、直前の簡略版より入力文字数は増えています。LLM呼び出し回数は同じ4回です。速度・費用・品質への影響はDifyでの実測が必要です。

## Difyへの取り込み

1. YAMLをインポートし、ナレッジ検索ノードに目的のナレッジが選択されていることを確認します。
2. ナレッジの「メタデータ」で組み込みメタデータを有効にします。Difyでは初期状態で無効です。文書名が `johokiso3-1-2.html` と一致している必要があります。名前が異なる場合は検索ノードのフィルター値を実際の名前に変更してください。
3. プレビューで `mode` を `generate_question`、メッセージを「問題を1問生成してください。」として実行します。`topic` と `conversation_context` は空欄でも動く構成です。
4. 検索結果が取得でき、問題と選択肢が教材内に収まっていることを確認して公開します。資料が取得できない場合、アプリ側には問題として表示されません。

既存アプリ内でフローを更新する場合は、そのアプリのAPIキーを引き続き利用します。別アプリとして作る場合は接続先APIキーも切り替える必要があります。

## 確認範囲と比較

ローカルでYAMLの解析、グラフの接続、変数参照、元のモデル設定・通常会話設定の維持を確認しています。Dify上へのインポート、実行時間・品質の測定は未実施です。

教材限定は検索対象の指定とLLMへの指示で行います。LLMの資料外の補完を機械的にすべて検出する構成ではありません。品質比較では問題だけでなく選択肢・解説も教材と照合してください。

引用出力を減らした分の負荷軽減は見込めますが、4回のLLM呼び出しと検索結果の入力は残ります。短縮幅は実測が必要です。モデル比較は、この同じフロー・同じ教材・同じ入力条件で行ってください。
